# Troubleshooting Guide

| Symptom | Likely Cause | Diagnostic Steps | Fix |
| --- | --- | --- | --- |
| Credential exposure detected in repo or CI | Secret scanning warning from TruffleHog or committed `.env` values | Check `.github/workflows/main.yml` for TruffleHog step; inspect repo history for `.env` or secret-like strings | Remove secrets from repo, rotate exposed credentials, add `.env` to `.gitignore`, and ensure CI scans pass |
| Port conflict on startup | Docker Compose service port already in use (3000, 3001, 8080, 9090, 9093, 3005) | Run `docker ps` and `netstat -ano | findstr` for conflicting ports | Stop conflicting process or change exposed port mappings in `docker-compose.yml` |
| MongoDB Atlas auth failure | Invalid `MONGO_URI`, bad Atlas credentials, or IP access restrictions | Verify `MONGO_URI` against Atlas connection string; check Atlas Network Access IP whitelist; inspect backend logs | Correct `MONGO_URI`, update Atlas IP access list, and restart backend service |
| CORS errors in frontend/backend | Frontend requests blocked by backend or Render proxy, or `BACKEND_URL` misconfigured | Review browser console and `Access-Control-Allow-Origin`; inspect `NEXT_PUBLIC_API_URL` and `BACKEND_URL` values | Set `NEXT_PUBLIC_API_URL` and `BACKEND_URL` appropriately for environment, and ensure backend CORS middleware allows the frontend origin |
| TruffleHog scan failures in CI | Repository contains secret-like strings or rejected patterns | Review workflow logs from `trufflehog git file://.` step | Remove or obfuscate secrets from source, commit only environment examples, and rerun CI |
| GHCR image pull failure on Render | Invalid image tag, missing registry permissions, or wrong Render registry creds | Check Render service deploy logs, verify `ghcr.io/...` image tags, and inspect `render.yaml` registry config | Ensure GitHub Actions pushes images successfully, grant `brainbytes-dchr-pull` permissions, and correct image URL/tag in Render deploy hook |
| Render cold start / slow deploy | Free-tier service startup latency or dependency initialization | Review Render deployment logs and startup health checks | Allow additional startup time; optimize app startup; use Render health check and retry if needed |
| Failed Render health check | Backend or frontend service is not responding on expected path | Inspect `render.yaml` `healthCheckPath` and live endpoint status | Fix service startup errors, ensure `/health` returns 200 for backend, and verify frontend root path returns 200 |
| Prometheus scrape failure | Prometheus cannot reach backend or exporter target | Check `monitoring/prometheus.yml` scrape targets and `docker compose logs prometheus` | Ensure `backend:9080`, `node-exporter:9100`, `cadvisor:8081`, and `alertmanager:9093` are reachable from Prometheus container |
| Alertmanager routing failure | Alertmanager webhook or route misconfiguration | Review `monitoring/alertmanager.yml` and Alertmanager logs | Confirm receiver URL `http://backend:3000/api/alerts` is correct and backend is available; restart Alertmanager if needed |
| Grafana provisioning does not show dashboard | Provisioning path or datasource misconfiguration | Inspect `monitoring/grafana/provisioning/datasources/datasource.yml` and `dashboards.yml`; check Grafana logs | Fix datasource environment vars, ensure provisioning directory is mounted, and restart Grafana container |
| Grafana alerts not firing | Grafana alert provisioning is present but not yet validated end to end, or the rule query/threshold does not match the live metrics | Review `monitoring/grafana/provisioning/alerting/alerts.yaml` for the configured alert group and rule expressions; verify Grafana Cloud credentials and remote write settings are correct; confirm the metric names and labels used by the alert match those emitted by Prometheus; manually trigger a test condition if possible to confirm the alert becomes active | Check Grafana and Prometheus logs, verify the alert query against the live metric series, and use a controlled test condition to confirm the alert fires and resolves as expected |
